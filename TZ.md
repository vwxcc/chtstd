# ChatStudio — техническое задание и план

## 1. Концепция

ChatStudio — приватный веб-интерфейс для общения с ИИ в формате персонального AI-чата.

- регистрация и вход;
- личные чаты пользователя;
- история чатов;
- поиск по приватным чатам;
- загрузка и библиотека файлов;
- настройки и аккаунт;
- никакой публичной стены, публичных постов, лайков или общей ленты;
- данные пользователей и чатов хранятся на сервере.

## 2. Визуальный стиль — Claude

Интерфейс должен быть визуально ориентирован непосредственно на предоставленный пользователем референс «@Chat Studio — чат в стиле Claude.html».

Цель: ощущение интерфейса Claude, а не просто обычного AI-чата.

Требования:
- чистый минималистичный интерфейс;
- светлая тёплая/нейтральная палитра;
- аккуратная типографика и большие читаемые отступы;
- визуально спокойные карточки и элементы;
- минимум лишних границ и декоративных элементов;
- скругления, размеры, расстояния и иерархия элементов должны быть близки к референсу;
- сообщения пользователя и ИИ должны иметь аккуратную, хорошо читаемую структуру;
- composer внизу чата должен выглядеть как основной центральный элемент;
- sidebar должен быть постоянной частью интерфейса после авторизации;
- адаптивность для ПК и мобильных экранов;
- состояния hover/focus/loading/error должны быть выполнены в том же визуальном языке;
- кнопки закрытия, меню и модальные окна — аккуратные и ненавязчивые;
- не копировать логотипы, фирменные материалы или закрытые элементы Claude; воспроизводится именно общий UX/UI-язык, указанный в референсе.

## 3. Авторизация

- регистрация;
- вход;
- выход;
- сессия через безопасную cookie;
- CSRF-защита;
- ограничение частоты запросов;
- администраторы определяются через конфигурацию.

## 4. Sidebar

После авторизации sidebar всегда доступен.

Содержит:
- новый чат;
- историю приватных чатов;
- поиск по чатам;
- аккаунт;
- настройки;
- библиотеку файлов;
- дополнительные пункты по мере появления функций.

## 5. Чат

- создание нового приватного чата;
- отправка сообщений;
- потоковая генерация ответа;
- продолжение диалога;
- отображение ошибок;
- остановка генерации;
- отображение использованной модели;
- сохранение истории;
- автоматическое название чата;
- длинные ответы с нормальным Markdown/code rendering;
- корректное отображение файлов и вложений.

## 6. Файлы

- загрузка файлов в чат;
- отдельная библиотека файлов пользователя;
- привязка файлов к сообщениям;
- ограничения размера;
- ограничения количества файлов;
- обработка PDF/DOCX/TXT/изображений и других поддерживаемых форматов;
- безопасное хранение файлов.

## 7. AI Router

Система должна поддерживать несколько AI-провайдеров.

- несколько endpoint/model;
- маршрутизация запросов;
- fallback при недоступности модели;
- учёт занятости/лимитов;
- глобальное ограничение параллельных AI-запросов;
- таймауты;
- настройки температуры и max tokens через environment;
- логирование AI-запросов;
- восстановление прерванных запросов.

Базовый Qwen-провайдер:
- Base URL: https://llm.stage.satel.org/v1
- Model: qwen36-35b
- Temperature: 0.2
- Max tokens: 32000
- Concurrency: 2

## 8. Backend

Стек:
- Python;
- FastAPI;
- SQLAlchemy async;
- SQLite на первом этапе;
- SSE для потоковых ответов;
- отдельный слой AI Router;
- отдельные API routers.

Текущая структура:
```
app/
├── __init__.py
├── main.py
├── config.py
├── database.py
├── auth.py
├── ai_router.py
├── generation.py
├── schemas.py
├── file_processing.py
└── routers/
    ├── __init__.py
    ├── auth.py
    ├── chats.py
    ├── files.py
    ├── messages.py
    ├── requests.py
    ├── admin_routing.py
    └── shared.py
```

## 9. Deployment

Целевой сервер — ZimaOS.

- Docker;
- приложение внутри контейнера слушает 8000;
- внешний порт: 3050;
- persistent volume для data;
- persistent volume для uploads;
- конфигурация через .env;
- запуск через `uvicorn app.main:app --host 0.0.0.0 --port 8000`.

## 10. План разработки

1. Привести backend к корректной структуре — выполнено.
2. Проверить импорты, зависимости, запуск FastAPI и создание БД — выполнено; CI проходит после исправления FastAPI 204 delete endpoints.
3. Проверить и при необходимости исправить API авторизации — выполнено; проверены cookie-сессия, CSRF, rate limit, password hashing, duplicate-email handling и admin checks.
4. Проверить чаты, сообщения и SSE-генерацию — следующий этап.
5. Проверить файловую систему и обработку вложений.
6. Проверить AI Router и Qwen-провайдер.
7. Собрать frontend в стиле предоставленного Claude-референса.
8. Соединить frontend с API.
9. Полностью проверить сценарии регистрации → чат → сообщение → ответ → история → файлы.
10. Подготовить Docker/ZimaOS deployment.
11. Финально проверить production-конфигурацию и безопасность.
