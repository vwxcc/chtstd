# CHTSTD Python Sandbox Bot

A private Telegram bot that executes Python code sent by allowlisted users. It does not call an AI model: write code in DeepSeek on your phone, then send its entire answer to the bot in one message or as a .py/.txt attachment.

## Features

- /start sends copy-ready instructions and the code-block protocol for DeepSeek.
- Unmarked content is treated as one Python script.
- Optional PYTHON, INPUT, and FILE blocks are parsed and run in order.
- Python blocks share a temporary workspace; later blocks can use files produced by earlier ones.
- If input() has no preset INPUT value, the bot asks for a value in Telegram and resumes the same Python process.
- Returns stdout, stderr, exit codes, timeouts, and generated files such as DOCX, PPTX, XLSX, SVG, CSV, JSON, PNG, or ZIP.
- Strict Telegram user-ID allowlist, one global worker, bounded queue, /status, /cancel.
- /healthz endpoint for Render and Better Stack monitoring.

## Message protocol

```text
[[[PYTHON:main]]]
name = input("Name: ")
print("Hello", name)
[[[END]]]

[[[INPUT:main]]]
Timur
[[[END]]]

[[[FILE:results/info.txt]]]
Generated by the sandbox
[[[END]]]
```

Python task identifiers must be unique. INPUT names must match Python task names; input values are passed line by line. If a program requests more input than supplied, the bot asks for it interactively in Telegram. FILE contents are written as UTF-8 under the temporary workspace; absolute paths, parent traversal, and dot-prefixed paths are rejected. Without markers, the message is executed as one Python program named main. For very long code, attach a .py or .txt file.

## Deploy on Render

1. Create a bot with @BotFather and copy its token.
2. Create a Render Web Service using this repo; render.yaml includes build/start commands and the /healthz health check.
3. Set TELEGRAM_BOT_TOKEN in Render environment variables.
4. Set ALLOWED_USER_IDS to your numeric Telegram user ID. ADMIN_USER_IDS can hold additional allowlisted IDs. Keep these lists private; if empty, code execution is denied.
5. Deploy and configure Better Stack to monitor https://YOUR-SERVICE.onrender.com/healthz.
6. Send /start to the bot.

Use exactly one Render instance because Telegram long polling and the queue are in memory. On free Render, active/queued jobs and temporary files can be lost on restart. Better Stack pings may help keep an instance warm but cannot guarantee continuous uptime.

## Limits and security

The executor uses a child process with a stripped environment, temporary workspace, timeouts and Linux CPU, address-space, file-size, open-file, and core-dump limits. Source, queue, output, and artifact sizes are bounded. The executor does not install packages for submitted code.

**Security warning:** a subprocess plus resource limits is not a strong sandbox. Network access is not fully blocked and filesystem isolation from the host is not guaranteed. Keep this private, allowlist only trusted users, and never run untrusted code. Strong isolation requires a separate container/service with network and filesystem restrictions.

## Environment variables

See env.example. Required: TELEGRAM_BOT_TOKEN and at least one numeric ID in ALLOWED_USER_IDS or ADMIN_USER_IDS.

- MAX_QUEUE_SIZE=5: number of waiting tasks, not counting the active job.
- TASK_TIMEOUT_SECONDS=12: compute window per Python block between input prompts, capped at 30 seconds.
- TASK_MEMORY_MB=256: child address-space limit, capped at 384 MB.
- INPUT_TIMEOUT_SECONDS=120: waiting time for each interactive input, capped at 300 seconds.
- MAX_SUBMISSION_BYTES=900000: message-size limit.
- MAX_ARTIFACT_FILES=40, MAX_ARTIFACT_TOTAL_BYTES=41943040, MAX_ARTIFACT_FILE_BYTES=15728640: output limits.

## Local development

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp env.example .env
# Add TELEGRAM_BOT_TOKEN and ALLOWED_USER_IDS to .env
uvicorn bot:app --reload --port 8000
```

Never commit .env or real bot tokens.
